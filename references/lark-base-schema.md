# 飞书多维表格结构

## 初始化原则

- 默认 Base 名称：`需求分拣机`。
- 默认创建两张表：`需求池`、`Bug池`。
- 两张表必须位于同一个飞书多维表格 Base 内。
- 字段名使用中文，便于业务用户直接查看；命令和字段类型按 `lark-cli base` 实际规范创建。
- 创建字段前必须读取 `lark-base` 的字段属性 reference。
- 写记录或查询前必须读取目标表真实字段结构。
- 若已有同名表，先读取结构并补齐缺失字段，不要删除用户已有字段。
- 初始化成功后，必须把 Base 链接、base token、两张表 table id 写入 `data/base-state.json`，供下次自动复用。

## Base 状态检查

处理用户反馈或查询需求前先检查是否有可用 Base：

1. 用户本次提供 Base 链接或 token：解析并验证；成功后更新 `data/base-state.json`。
2. 用户未提供 Base：读取 `data/base-state.json`，验证其中的 `base_token` 是否可访问。
3. 状态文件不存在、字段不完整或 Base 不可访问：创建新 Base，并在其中创建两张表。
4. 新 Base 创建成功后，立即写入 `data/base-state.json`。

状态文件只允许记录：

- `base_name`
- `base_token`
- `base_url`
- `tables`
- `updated_at`

不要写入 app secret、access token、tenant access token、cookie 或其他凭证。

## 需求池

用途：放所有非 Bug 的产品诉求、体验问题、机会线索和弱信号，用 `状态` 字段区分处理阶段。

写入时应优先根据上下文推断 `用户类型 / 来源渠道 / 影响范围 / 业务价值 / 优先级`。`未知`、`其他`、`未定` 只是兜底选项，不应作为默认写入值。

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| 需求标题 | 文本 | 用一句话描述真实问题，不直接照搬用户方案 |
| 用户原话 | 多行文本 | 原始反馈或关键证据 |
| 真实问题 | 多行文本 | 从用户反馈还原出的真实问题 |
| 使用场景 | 多行文本 | 用户在什么任务、流程、约束下遇到问题 |
| 用户类型 | 单选 | 免费用户、付费用户、企业客户、内部用户、未知 |
| 来源渠道 | 单选 | 客服、销售、社群、访谈、数据分析、应用商店、内部、其他 |
| 影响范围 | 单选 | 单个用户、少量用户、多个客户、核心客户、广泛影响、未知 |
| 业务价值 | 单选 | 高、中、低、未知 |
| 优先级 | 单选 | P0、P1、P2、P3、未定 |
| 状态 | 单选 | 待观察、待确认、待执行、执行中、开发中、已完成 |
| 缺失信息 | 多行文本 | 待确认时需要补充的问题、场景、影响或约束 |
| 下一步动作 | 多行文本 | PM 或团队接下来要做什么 |
| 负责人 | 人员 | 可选；没有人员字段权限时用文本字段替代 |
| 来源附件 | 附件 | 截图、文档、表格等原始材料 |
| 最近出现时间 | 日期 | 最近一次出现该反馈的时间 |
| 创建时间 | 创建时间 | 系统字段 |

建议视图：

- `待观察`：状态为待观察。
- `待确认`：状态为待确认。
- `待执行`：状态为待执行。
- `执行中`：状态为执行中。
- `开发中`：状态为开发中。
- `已完成`：状态为已完成。

## Bug池

用途：放明确故障、异常、不可用、与预期不符、可复现或疑似可复现的问题。

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| Bug标题 | 文本 | 一句话描述异常 |
| 用户原话 | 多行文本 | 原始反馈 |
| 复现描述 | 多行文本 | 复现步骤；未知时写缺失项 |
| 期望结果 | 多行文本 | 用户或产品预期 |
| 实际结果 | 多行文本 | 实际发生了什么 |
| 严重程度 | 单选 | S0阻塞、S1严重、S2一般、S3轻微、未知 |
| 环境信息 | 多行文本 | 设备、系统、浏览器、版本、账号、页面 |
| 原因反馈 | 多行文本 | 故障原因、根因、修复原因、处理结论；未知时留空 |
| 来源渠道 | 单选 | 客服、销售、社群、访谈、监控、内部、其他 |
| 状态 | 单选 | 待确认、待复现、待修复、修复中、待验证、已修复、无法复现、关闭 |
| 负责人 | 人员 | 可选；没有人员字段权限时用文本字段替代 |
| 修复截止 | 日期 | 需要时填写 |
| 来源附件 | 附件 | 截图、录屏、日志、文档 |
| 最近出现时间 | 日期 | 最近一次反馈时间 |
| 创建时间 | 创建时间 | 系统字段 |

建议视图：

- `待修复`：状态为待确认、待复现、待修复、修复中。
- `严重 Bug`：严重程度为 S0阻塞 或 S1严重。

## 初始化后的反馈

初始化完成后回复：

```text
需求分拣机已初始化：
- Base：<名称和链接>
- 需求池：已创建/已补齐
- Bug池：已创建/已补齐

你之后可以直接把截图、聊天记录、表格或文档丢给我，我会先分析并确认拟写入池子和需求状态，再写入对应表。
我已将这个 Base 的链接和表 ID 记录到 `data/base-state.json`，下次会默认复用。
```
